# AskData Project Instructions

`codex.md` is the living session handoff and active-phase ledger for this repository. Read it before substantive project work in every new session.

- Treat `SPEC.md` as the product and system contract.
- Treat `askdata-impl-plan.md` as the complete phase roadmap and detailed implementation authority.
- Use the active-phase snapshot in `codex.md` for the current scope. Consult only the relevant sections of the larger documents unless the task requires broader context.
- Work on one implementation phase at a time. Do not create artifacts for later phases.
- Do not mark work complete from intention or file presence alone. Record the exact verification command and result.
- After every implementation change, update both the living progress record in `askdata-impl-plan.md` and the current state, implemented paths, verification evidence, decisions, and work log in `codex.md`.
- Do not advance to the next phase until every acceptance criterion for the active phase passes and the user explicitly asks to continue.
- When advancing, replace the active-phase snapshot in `codex.md` with the next phase's actionable plan and retain the completed phase in the progress history.
